Ensuite sur le PC BNP :

git pull origin GIL-General

Puis tu peux lancer l’extracteur JIRA normalement, sans redirection :

node \
  portal/commun/scripts/qualite/standalone/extraction/jira/extraire_capabilities.js

et après le run :

echo "EXIT_CODE=$?"

Puis on contrôle AERL_GIL-206 avec :

python - <<'PY'
import json
from pathlib import Path

p = Path(
    "portal/commun/data/standalone/jira/"
    "capabilities_brut.json"
)

data = json.loads(
    p.read_text(
        encoding="utf-8",
        errors="replace"
    )
)

for row in data.get("capabilities", []):

    epic = row.get("epic") or {}

    if epic.get("key") != "AERL_GIL-206":
        continue

    print("EPIC =", epic.get("key"))
    print("ENFANTS =", len(row.get("children") or []))

    for child in row.get("children") or []:

        fields = child.get("fields") or {}

        print(
            child.get("key"),
            "|",
            fields.get("summary"),
            "| statut =",
            (fields.get("status") or {}).get("name"),
            "| type =",
            (fields.get("issuetype") or {}).get("name"),
        )

    print()
    print("DIAGNOSTICS =")

    for diag in row.get("childrenDiagnostics") or []:
        print(diag)

    break

SI GREENHOPPER RETOURNE 0
------------------------------------------------------------

Si le résultat contient :

[JIRA][N2][GREENHOPPER] ... => 0 ticket(s)

ou :

source = parent-fallback

conserver toute la sortie.

Cela indiquera que Jira exige certains paramètres dynamiques
fields/panels supplémentaires dans le POST AjaxIssueAction.

Ne pas modifier manuellement les IDs de champs.
Ils devront être récupérés dynamiquement.
