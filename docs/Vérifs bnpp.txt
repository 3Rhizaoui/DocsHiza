La prochaine étape doit se faire sur le PC BNP, depuis la racine du dépôt. On va exécuter uniquement l’extraction JIRA Standalone et enregistrer tout le diagnostic :

node \
  portal/commun/scripts/qualite/standalone/extraction/jira/extraire_capabilities.js \
  2>&1 | tee jira_capabilities_diag.log

Comme d’habitude, connecte-toi à JIRA si nécessaire et appuie sur Entrée lorsqu’il le demande.

Une fois terminé, vérifie d’abord que le vrai fichier contient bien les 13 :

python - <<'PY'
import json
from pathlib import Path

p = Path(
    "portal/commun/data/standalone/jira/"
    "capabilities_brut.json"
)

data = json.loads(
    p.read_text(
        encoding="utf-8",
        errors="replace"
    )
)

rows = data.get("capabilities") or []

print("CAPABILITIES =", len(rows))

for row in rows:

    epic = row.get("epic") or {}

    print(
        epic.get("key"),
        "|",
        (epic.get("fields") or {}).get("summary"),
        "| enfants =",
        len(row.get("children") or [])
    )
PY

Sur BNP nous voulons retrouver quelque chose comme :

CAPABILITIES = 13
AERL_GIL-206 | [FEATURE GIL] - GED | enfants = ...
...

Ensuite, le diagnostic essentiel :

grep -n -A40 -B5 \
  '\[CAPABILITY\].*AERL_GIL-206' \
  jira_capabilities_diag.log

Et également :

grep -n -E \
  'JIRA CHILD QUERY|JIRA CHILD QUERY ERROR' \
  jira_capabilities_diag.log

C’est ce résultat qui nous dira pourquoi les 10 tickets visibles dans l’Epic GED ne remontent actuellement pas.

Enfin, une fois le vrai JSON BNP généré, on regardera les champs de AERL_GIL-206 avec :

python - <<'PY'
import json
from pathlib import Path

p = Path(
    "portal/commun/data/standalone/jira/"
    "capabilities_brut.json"
)

data = json.loads(
    p.read_text(
        encoding="utf-8",
        errors="replace"
    )
)

for row in data.get("capabilities", []):

    epic = row.get("epic") or {}

    if epic.get("key") != "AERL_GIL-206":
        continue

    print(
        json.dumps(
            row,
            ensure_ascii=False,
            indent=2
        )
    )

    break
PY

On s’arrête après ces trois résultats. Ensuite je pourrai déterminer précisément si on doit corriger la relation Epic → tâches, enrichir les champs Epic, ou les deux. La partie Octane validée reste totalement intacte.
